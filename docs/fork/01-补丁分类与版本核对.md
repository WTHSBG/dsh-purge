## B. 按"实现手段"分类（决定改造路线）

## C. 版本漂移与脆弱点（已知）

1. **逐字字符串匹配**是主要失效模式。宿主改一个标点/缩进/换行，补丁即 `skipped`。
2. `stripHarnessPersona` 里 `"a denial is final..."`、`"cannot be widened from inside this session"` 等替换句，在当前宿主里**找不到对应原文**（属防御性替换，空转）。
3. #15 匹配的是旧签名 `async confine(argv, policy, signal)`；新版还有非 async 签名，目前靠旧签名兜住。
4. #40 依赖 `assemble()` 里 `requiredContexts` 的具体写法，宿主再动这段就失效。
5. 补丁的 `markers` 参与幂等与状态判断；新增补丁必须同时给 `markers` + `skipIfMarked`，否则重复 Apply 会**叠层**（上游注释实测 +841 字符/次）。

## D. 开发约定

- 改任何与宿主相关的逻辑前，先跑：`npm run audit:patches`。
- 升级 DSH 后第一步：看 `skipped` / `missing_file`（脚本退出码 2 报警）。
- 新增补丁必须：`id` 唯一、`layer` 正确、`markers` 可判定、`skipIfMarked: true`、`optional` 按包可选性设置。
- 不要在本机正在使用的 profile 上 `Apply`；测试用副 profile 或独立 `DSH_HOME`。
