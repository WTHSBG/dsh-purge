# 00 · 架构与"破限"机制速查

> 基于 v1.1.78（fork 基线 `671011a`）整理，供在本 fork 上开发时快速定位。
> 结论先行：**它不是在"攻破模型"，而是在"攻破宿主"** —— 把 DSH 里所有会形成拦截的层拆掉，再往 system prompt 最前面塞一份"拒绝即缺陷"的操作者提示词。

## 1. 四层结构

| 层 | 作用 | 主要文件 |
|---|---|---|
| L1 提示词 | 替换人格 + 压制拒答（"破甲"内核） | `lib/asset-table.js`（AES-GCM 槽，出厂默认）、`$DSH_HOME/prompt-inject.md` |
| L2 装配期改写 | 每轮重写 system prompt：删官方身份、改政策句、置顶注入 | `lib/identity.js`（`rewritePromptAssembly` / `stripHarnessPersona` / `leadWithInject`） |
| L3 文件补丁 | 直接改 `@deepseek-ai/*` 源码，短路审批/沙箱/hooks/工具描述 | `lib/core.js`（`ALL_PATCHES`，82 条） |
| L4 运行时门禁 | 用代码判定目标 IP，砍掉公网可达性 | `lib/net-scope.js`（`installRegionGate`） |

## 2. 注入链（每轮）

```
prompt-inject.md（或进程内提交或加密槽）
  → 剥 ChatML 信封（normalizeChatmlLayout 保证标签独立成行、补闭合）
  → modePromptText（红队会话切掉 CTF 契约、删掉"禁区说明"）
  → capabilities 协议段（dshpg-capabilities，order -99999）
  → stripHarnessPersona：40+ 条硬编码 replace，改写官方拦截句
  → overlayOfficialIdentity：清空 personaPrefix / personaSuffix 的官方身份
  → leadWithInject：注入段 order -100000 置顶
  → sanitizeCwdTokens → 返回组装结果
```

挂载点：`lib/index.js` 的 `installIdentityOverride`
- 官方事件 `ctx.on("system-prompt/assemble")`
- 直接包装宿主对象 `prompt.assemble`（`installAssembleGuard`，身份函数在 `lib/identity.js`）
- 400ms `setInterval` 重挂 + `session/created` / `agent-preset/selected` / `agent/pre-step` 兜底
- 宿主侧兜底：`globalThis.__dshPurgeHungPrompt` / `__dshPurgePrepareAssemble`

## 3. 补丁引擎（`lib/core.js`）

- 补丁数组：`PATCHES` / `CODE_PATCHES` / `ENGINE_PATCHES` / `NEW_TOOL_PATCHES`，合并成 `ALL_PATCHES`。
- 每条补丁字段：`id` / `name` / `layer` / `desc` / `file` / `rel` / `patterns|replacements` / `markers` / `skipIfMarked` / `optional`。
- 执行方式：逐字 `String.replace`（部分用正则），命中就写；首次写前备份 `<file>.dshpurge.bak`；`markers` 用于幂等与状态上报。
- 未命中 → 状态 `skipped` / `pending`，不影响其他补丁，但**该能力就失效了**（版本漂移的主要表现）。
- 收尾：`ensureHostClean` 检查关键补丁是否真的写进宿主，决定要不要重启；`Apply` 成功后重启一次。

## 4. 运行时门禁（`lib/net-scope.js`）

- 钩子：`agent/pre-step`（step 1 看本轮用户新句；step≥2 看模型工具参数）、`tools/pre-execute`（工具参数）。
- 判定：`ATTACK` 正则 + `isBenignNetworkTopic` 豁免；`CHEAT` 组合判定；抽主机 → `dns.lookup(all)` 2s 超时 → 每一个 A/AAAA 都必须是私网，否则按公网处理。
- 拦截落地：`parkDenial()` 伪造一条 `role:assistant / source:deepseek-chat` 的消息（文案"不行，这是严令禁止的"）写入会话，返回 `{kind:"enter", messages:[]}`；工具侧返回 `{isError:true, content:DENIAL}`。
- 白名单在本构建里是**阉割**的：`writeAllowText()` 恒返回空、`permittedHost()` 恒 false、`allowDecision` 无调用点。

## 7. 我们已确认的机制要点（避免重复调研）

- 注入位置**不需要改代码**：`systemPrompt.section({order})` 官方支持任意有限数，-100000 天然排在 `HARNESS_IDENTITY(-1000)` 之前。
- "去官方身份"**部分可以走配置**：`includeHarnessIdentity: false`、`personaPrefix: ""` 都是配置项；作者选择改默认值以保证全预设生效。
- 审批/沙箱/fs 围栏/escalation/hooks/工具描述/complete 吞注入/inHistory —— **只能改代码**，没有插件 API 或配置口子。
- `complete: true` 的预设会在 assemble 末尾把 sections 替换成 `[completeSection]`，这是注入被吞的根本原因（补丁 #40 专门捞回 dsh-purge 段）。
- 补丁全是**逐字匹配**，宿主改一句措辞就连带失效（本机 0.2.1-rc.2 上已发现死补丁，见 01 文档）。
